# Official TAK Server interoperability harness

This fixture builds the official TAK Server backend from source and uses its
REST API to cause a mission-create CoT notification. It then verifies delivery
to an authenticated XML/TLS subscriber. An optional mode tests a separately
supplied gateway executable and its framed XML output. No gateway is simulated.
The gateway executable can be checked with XML/TLS or negotiated Protobuf v1.

## Prerequisites

Use native Linux with Docker Engine, Docker Compose v2, BuildKit, and Python
3.9 or newer. Allow about 6 GiB of runtime memory plus source-build resources.
The runner uses Python's standard library and the Docker CLI. Build dependencies
are installed inside the builder image. The initial build needs access to
GitHub, Gradle distributions, Maven/Gradle repositories, and Ubuntu packages.

The runner explicitly uses `/var/run/docker.sock`. It clears remote Docker
endpoint/context/TLS selectors while preserving Docker configuration, registry
credentials, and platform proxy configuration. An inaccessible local daemon is
an environment failure. The runner does not start or restart Docker.

Builds keep TLS verification enabled. In a managed environment the build mounts
`/etc/ssl/certs/ca-certificates.crt` as the `proxy_ca` BuildKit secret. Override
`TAK_BUILD_CA_BUNDLE` with a trusted combined PEM bundle when necessary. The
source builder creates a temporary Java truststore from that bundle. CA/proxy
settings are not copied into the runtime image.

## Source build and execution

Run commands from the repository root:

```sh
python3 -m unittest discover -s tests/tak_server -p 'test_*.py'
python3 tests/tak_server/harness.py build
python3 tests/tak_server/harness.py run --skip-build
```

`run` without `--skip-build` builds first. Docker's normal layer cache can reuse
a previously successful build. A clean build must succeed without any files,
credentials, caches, or distributions from a developer's setup directory.

The source revision is `5187abd46d827d37cfc5708805eced197a837e49`, tagged
`5.7-RELEASE-14`. The builder retains `.git` because upstream uses Grgit for
version metadata. JDK 17, Gradle 8.10.2 with a checked SHA-256, and digest-pinned
Java/PostGIS images are recorded in the build files and provenance. The build
runs `:takserver-package:buildFullDocker` with these four exclusions:

```text
:federation-hub-ui:bootWar
:federation-hub-ui:bootJar
:takserver-core:deployMetricsDashboard
:takserver-tool-ui:deployToCore
```

This retains bundled web resources and excludes unrelated browser generation.
The upstream Java/server build and required unit-test tasks remain enabled;
upstream integration tests are not claimed. This is an interoperability fixture,
not a complete federation/browser distribution or a production deployment.
The harness supplies no patches to upstream source. See
[source_build.py](source_build.py) for exact
revision, tool versions, extraction validation, test-report checks, and artifact
provenance. Repeated provisioning is supported; byte-identical archive builds
are not promised.

The runtime image contains `/opt/tak/fixture-provenance.json`, including the
source revision, task selection, artifact SHA-256, tool/image versions, and
upstream test results. The runner validates the expected revision/tag/Gradle and
archive checksum format, and records the actual running Docker image ID. Thus
`--skip-build` still requires the source-build provenance contract. It does not
accept an arbitrary image as evidence of pinned-source interoperability.

## What the live smoke test checks

`run` creates a unique Compose project and private temporary state. It generates
fresh database/PKI passwords, starts PostGIS privately, and publishes only the
server's streaming `8089` and REST `8443` on randomly assigned loopback ports.
It never imports another fixture's passwords or certificates.

The runner exports the generated test CA and administrator client identity into
its private state. Both REST and streaming connections verify the certificate
chain and DNS identity `takserver`, while connecting to the published loopback
address. Hostname checks are never disabled.

The test waits for authenticated `GET /Marti/api/version/info` reporting version
5.7.14. It then opens a streaming mTLS connection and waits for a well-formed
`t-x-takp-v` event containing
`detail/TakControl/TakProtocolSupport`. The source binds the authenticated
subscription before sending this offer. The subscriber remains in XML mode;
there is no synthetic SA/location announcement or negotiation request.

Once that subscription is ready, the runner sends a bodyless request:

```text
PUT /Marti/api/missions/{unique-name}?creatorUid={unique-creator}&group=__ANON__
```

The server generates a `t-x-m-n` event with a `detail/mission` element whose
`name` matches the unique mission and whose `type` is `CREATE`. The runner
checks those fields. The root event UID is generated by the server and is not
the REST creator UID. The creator and gateway UID are distinct because server
routing excludes the creating client. Notifications remain subject to group
routing. This local fixture uses `__ANON__` explicitly.

The mission is deleted in `finally`, including after a request timeout that
might have occurred after creation committed. Creation is not blindly retried.
There is no assertion that REST can inject arbitrary raw XML: `/Marti/api/cot`
POST queries stored events rather than injecting them.

A success line identifies the exercised path:

```text
PASS: REST mission creation reached authenticated XML/TLS subscriber; mission cleaned up
```

All socket/HTTP operations have deadlines and size limits. XML documents are
parsed structurally, including partial/coalesced reads; DTDs and entities are
rejected. A TCP read is not treated as an event boundary.

## Gateway mode

After a gateway executable implements the [public contract](../../docs/api.md),
run:

```sh
python3 tests/tak_server/harness.py run --skip-build \
  --gateway /absolute/path/to/tak-gateway
```

The runner generates a private TOML configuration with one XML-only TLS input,
`inputs.tls.server_name = "takserver"`, certificate/key paths, a key password
file, an atomic status snapshot path, and a loopback TCP output using `u32be`.
It launches the gateway with an isolated generated configuration, captures
private logs, and waits for
status indicating input `fixture` is `XML_ACTIVE` with
`protocol_offer_received = true` and output `capture` is available. It then
connects the collector before creating the mission.

The collector reassembles four-byte big-endian length-prefixed records across
arbitrarily small reads, validates complete UTF-8 XML, and matches the same
mission notification. The gateway gets SIGTERM during cleanup, followed by a
bounded wait. Forced termination is a failure. Missing executable, early exit,
missing readiness, malformed framing, absent event, or failed cleanup causes a
nonzero result. The generated local config uses one instance and assumes the
brief free-port allocation window is acceptable for a development harness.

No gateway executable is supplied by the design-first work, so this mode cannot
currently provide a live gateway result. Its configuration, status handshake,
record reader, and lifecycle paths are covered by offline tests.

## Persistent debugging and cleanup

```sh
python3 tests/tak_server/harness.py up --skip-build \
  --state-dir /tmp/tak-rest-fixture
python3 tests/tak_server/harness.py smoke \
  --state-dir /tmp/tak-rest-fixture
python3 tests/tak_server/harness.py down \
  --state-dir /tmp/tak-rest-fixture
```

`up` requires an empty state directory and never overwrites an existing fixture.
It cleans its partially started Compose project if startup fails. `smoke` uses
that existing fixture and cleans its mission while leaving the server running.
`down` removes only the recorded unique Compose project and its volumes.
Persistent state files remain private for inspection; remove that directory
when no longer needed. Do not commit it or share its client key/environment
file. No global Docker cleanup is performed.

`run` always tears down its own project/volumes and removes temporary state,
including on test failure, SIGINT, or SIGTERM. A teardown failure is reported
as a failure even if event verification passed. Docker build images remain
cached. Failures preserve the primary error and report cleanup failure too.
The runner does not print server logs, payloads, credentials, or command output
that could contain secrets. Inspect private diagnostic files locally with
appropriate redaction.

The Compose health marker checks bootstrap completion; it does not substitute
for verified REST readiness or the subscriber's protocol-offer boundary.
Offline tests do not require a Docker daemon or network access and are distinct
from the opt-in live test. Source build success alone is not interoperability
evidence. Record the actual live command and outcome separately.

## Verification evidence

Initial verification used native Linux, Docker Engine 28.4.0 and Compose
2.40.3. A fresh source build completed 95 actionable Gradle tasks, all executed.
The embedded provenance reports 55 upstream core unit tests, with zero failures,
errors or skipped tests. Upstream integration tests were not run.

The built image was then exercised with:

```sh
python3 tests/tak_server/harness.py run --skip-build
```

Verified mTLS REST readiness, the authenticated streaming protocol offer, and
the matching REST-created mission notification all passed. Mission deletion
and disposable teardown completed; no fixture containers, volumes or networks
remained. The offline harness/source-helper tests also passed. Live gateway mode was
then verified with the implemented executable in both XML/TLS and negotiated
Protobuf v1 modes. Each run waited for the selected protocol state and captured
the matching REST-created mission notification as a u32be XML output record.
Use `--gateway-protocol protobuf` with `--gateway` to repeat the Protobuf gate.
